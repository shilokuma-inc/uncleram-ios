## 概要

端末の本物のメモリを架空の巨大 AI 企業に「献上」し、回収される直前で手を引くチキンレース型ゲームです。数字は本物、回収は演出で、OS による強制終了は起こしません。

| 項目 | 内容 |
| --- | --- |
| 対応端末 | iPhone / iPad（iOS 18 以降）、Mac（macOS 15 以降）。初回から 3 つとも出す |
| ジャンル | 長押しワンボタンの押し引きゲーム。速達便は約 20 秒、定期便は 2〜3 分 |
| ターゲット | ミームを知るガジェット好き・ゲーマー・配信者（初回から 9 言語。「多言語対応」の節） |
| 売り | 端末ごとに献上できる上限が違うので、機種ごとに結果が変わる |

背景は、2026 年 10〜11 月の AI 需要によるメモリ高騰と、「個人の PC がメモリを抱えるのは非効率」という発言への反発です。本作は実在の人物や企業を出さず、「回収する側」という構図だけを借ります。

## ゲームルール

定期便は最大 5 ラウンド（合間に降りられる）、速達便とデイリーは 1 ラウンドです（プレイモードの節）。各ラウンドでは、長押ししている間だけメモリを献上し、指を離した時点で献上量が確定します。隠れた「回収ライン」を越えると、そのラウンドの献上分はすべて失われます。

| 用語 | 意味 | 値（初期案） |
| --- | --- | --- |
| 枠 | ラウンド開始時の `os_proc_available_memory()`。このアプリが使える残りメモリ | 端末ごとに異なる |
| 献上量 | 実際に確保して書き込んだメモリ量 | 長押し中に枠の 2%/秒から加速（「数値の初期値」の表） |
| 回収ライン | 越えるとラウンド失敗になる隠れたライン | 取引先ごとに枠の 50〜80% の間でランダム。1 割は低い「早期回収」（「ゲーム性の見直し」の節） |
| 安全ライン | どんな場合も越えない止め。回収ラインは必ずこれより手前 | 枠の 85%（残り 15% か 200MB の大きい方） |
| 納品 | 指を離して献上量を確定すること | — |

- **ヒント**: 回収ラインが近づくと、CEO の表情が変わる、回収飛行船の音が近づく、画面にノイズが走る、で 3 段階に知らせ、iPhone では振動でも伝えます（「音と振動」の節）。表示の強さには、わざと揺らぎを入れます。
- **スコア**: 献上量（MB）× ニアミス倍率です。回収ラインとの差が枠の 3% 以内なら ×3、10% 以内なら ×1.5 にします。定期便では、降りた時点までの合計が最終スコアです（回収されると 0。「ゲーム性の見直し」の節）。
- **回収（失敗）の演出**: ゲーム内の世界で起きる出来事として見せます。回収飛行船が画面を覆い、UI がピクセル単位で崩れ、「全メモリ回収完了」と表示されます。iOS のシステム画面やクラッシュ、ホーム画面は模倣しません（理由は審査ガイドライン照合表）。
- **解放**: ラウンドが終わるたびに、成功・失敗に関わらず確保したメモリを即座にすべて解放します。
- **監査イベント**: OS からメモリ警告が届いたら、「監査が入った」としてラウンドを中断します。プレイヤーのせいではないので、それまでの献上分は納品扱いにします。

（図: embed）

回収・監査・納品のどの終わり方でも、次のラウンドの前に必ず全メモリを解放します。

## プレイモード

ショート動画で広がる「短い 1 回」と、繰り返し遊ぶ「積み上げ」を、モードを分けて両立させます（2026-11-11 確定）。

| モード | 中身 | 長さ | 狙い |
| --- | --- | --- | --- |
| 速達便 | 1 ラウンドだけの一発勝負。デイリーも速達便で、全員同じ条件・1 日 1 回 | 約 20 秒 | ショート動画と SNS 投稿。遊んでいる画面をそのまま収録しても短く収まる |
| 定期便 | 最大 5 ラウンド。合間に降りて確定するか、倍率を上げて続けるかを選ぶ。クレジットが貯まり、強化と取引先の解放に使う | 2〜3 分 | やり込み。称号の昇格もこちらで進む |

- タイトル画面の主ボタンは速達便にし、初めての人でも 20 秒で 1 回遊べるようにします。
- 速達便の結果画面から「定期便で稼ぐ」へ誘導します。
- ランキングは、強化や保険が効かない速達便とデイリーだけで集計します。課金や遊んだ量で有利にならないようにするためです。

## 数値の初期値（試作で調整）

どの数値も試作で遊んでから調整する前提の叩き台です。

| 項目 | 初期値 |
| --- | --- |
| 献上の速さ | 枠に対する割合で決める。枠の 30% までは 10%/秒。30% から先は 5%/秒で始め、1 秒ごとに 10% ずつ速くなり、上限は 9%/秒（どの端末でも 55% まで約 7 秒、80% まで約 10 秒）。確保は 0.1 秒ごと |
| 回収ライン | カロック・ラボ: 枠の 50〜60%（早期回収なし）/ アロケート社: 55〜80%、1 割のラウンドは早期回収で 30〜50% / リアロック・データセンター: 60〜75%（ラウンド中に ±5% 動く。1 割は早期回収で 35〜50%、こちらは動かない）。どの取引先も、動いた後を含めて「安全ライン − 枠の 5%」を越えない |
| 取引先の倍率 | ×1.0 / ×1.5 / ×2.0 |
| ニアミス倍率 | 回収ラインとの差が枠の 3% 以内なら ×3、10% 以内なら ×1.5 |
| クレジット | 定期便で降りて確定した換算献上量 100MB ごとに 1 cr（換算献上量は「セーブデータと進行」の節） |
| 強化の価格 | ヒント精度アップ 1 段階 400 cr（3 段階）/ 長押し減速 300 cr / 回収保険 600 cr（使い切り） |
| リアロックの解放 | 換算献上量の累計 20GB |
| 称号の昇格 | 換算献上量の累計 50GB で優良提供者、250GB で模範的な提供者、1TB で名誉株主（定期便だけを数え、取引先の倍率はかけない） |

## セーブデータと進行

iPhone・iPad・Mac では枠の大きさが 10 倍以上違います（iPhone は 3GB 前後、Mac は最大 32GB）。そこで進行は「枠に対する割合」で数え、セーブデータは iCloud で共有します（2026-11-11 確定）。

| 項目 | 内容 |
| --- | --- |
| 換算献上量 | 納品した量を、枠 3GB の端末で遊んだ場合の量に置き換えた値。換算献上量 = 献上量 ÷ 枠 × 3GB |
| 換算献上量で数えるもの | クレジット、称号の昇格、リアロック・データセンターの解放 |
| 実際の量のままのもの | 画面の献上量、献上明細書、シェア画像、金額の表示、スコア、ランキング。機種の差は、割合で競う腕前スコアと、搭載メモリのクラス分けで吸収する（「ランキング」の節） |
| 例 | 枠 3GB の iPhone で 2GB 納品 → 換算 2GB。枠 32GB の Mac で 20GB 納品 → 換算 約 1.9GB |
| 保存先 | iCloud のキー値ストア（NSUbiquitousKeyValueStore）。サーバーは持たない。iCloud を使っていない人は端末の中だけに保存する |

- **進行の画面の表示**: 称号や解放条件の画面だけ「換算」と添え、「換算とは」の説明を 1 行置く
- **複数の端末で遊んだとき**: クレジットは「端末ごとの獲得量」と「端末ごとの使用量」を別々に保存し、合計して残高を出す。後から同期した端末の値で上書きされて消えることがない。累計は端末ごとの値の合計。称号と強化は足さずにまとめる（同じものは 1 つ、段階は大きい方）。残高がマイナスになったら 0 と表示し、次の獲得から差し引く
- **端末の区別**: アプリが初回起動時に作る乱数の ID を使う。ハードウェアの ID は使わない
- **デイリー**: 挑戦済みの日付も同期し、別の端末ではもう挑戦できないようにする。同期が遅れて 2 回遊べてしまうことはあり得るが、影響が小さいので許容する
- **課金**: 買い切りの商品は、StoreKit の購入履歴から各端末で復元する（iCloud には入れない）。投げ銭の回数（明細書の「特別賞与」欄）だけ同期する
- **設定**: iOS と Mac の両方で、iCloud のキー値ストアの権限を有効にする
- **プライバシー**: iCloud のデータは開発者には届かないので、App のプライバシー表記は変わらない

## 音と振動

BGM はパブリックドメインの行進曲とラグタイムを自分で打ち込み、絵と同じ 1900〜1910 年代の空気にそろえます。振動は手応えに加えて、回収ラインのヒントにも使います（2026-11-11 確定）。

### BGM と効果音

| 場面 | 音 |
| --- | --- |
| タイトル | 行進曲をゆったりと。蓄音機のようなこもった音質にする |
| 長押し中 | ラグタイムのループ。献上の速さに合わせてテンポが上がる（最大 1.5 倍） |
| 回収ライン接近 | 回収飛行船のプロペラ音が近づく（ヒントの 2 段階目） |
| 納品 | タイプライターのベルと判子の音 |
| 回収 | 曲がテープのように伸びて止まり、飛行船の汽笛 |
| リザルト | 行進曲の終わりの和音。明細書が印字される音 |

- **曲の候補**: スーザ「ワシントン・ポスト」（1889）「星条旗よ永遠なれ」（1896）、ジョプリン「メープル・リーフ・ラグ」（1899）「ジ・エンターテイナー」（1902）。作曲者はそれぞれ 1932 年・1917 年に亡くなっており、日本でも米国でも曲の著作権は切れている。国歌は使わない
- **権利の注意**: 既存の録音、MIDI、最近の編曲版の楽譜は使わない（録音や編曲には別の権利がある）。初版の楽譜から自分で打ち込み、参照した楽譜を素材の出典に記録する
- **音の鳴らし方**: AVAudioSession は .ambient にする。消音スイッチに従い、ほかのアプリの音楽を止めない
- **設定**: BGM と効果音の音量を別々に変えられるようにする
- **メモリ**: 音は圧縮したまま読み込み、合計 20MB 以内にする。音の分はラウンド開始前に読み込み、枠の計測より先に済ませる

### 振動（iPhone）

| 場面 | 振動（Core Haptics） |
| --- | --- |
| 長押し中 | 弱い連続振動。献上の速さに合わせて少しずつ強くなる |
| 回収ライン接近 | ほかのヒントと同じ 3 段階で、鼓動のような振動が加わる。段階が上がるほど間隔が短くなる（初期値: 0.8 秒 → 0.5 秒 → 0.3 秒） |
| 納品 | 短く強い 1 回 |
| 回収 | ガタガタと崩れる長めの振動 |

- **揺らぎ**: 鼓動の始まる位置と間隔にも、ほかのヒントと同じ揺らぎを入れる。振動だけで回収ラインが正確に分からないようにする
- **振動のない端末**: iPad と Mac では振動を使わず、音と画面のヒントだけにする。強さの差は小さいので、ランキングは端末の種類で分けない
- **設定**: 振動はアプリの設定で切れるようにする

## アクセシビリティ

長押しがつらい人、画面や音が分かりにくい人も、同じ勝負に参加できるようにします（2026-11-11 確定）。

| 項目 | 対応 |
| --- | --- |
| タップ操作 | 設定「タップで献上」。 1 回目のタップで献上を始め、もう一度タップすると納品。Mac ではクリックかスペースキーを 2 回。ランキングは長押しと区別しない |
| VoiceOver | ボタンは「献上する」と読み上げ、ダブルタップで開始、もう一度で納品（タップ操作と同じ）。ヒントの段階が上がると「会長が身を乗り出しました」などと読み上げる |
| 音のヒント | 飛行船の音は、画面の「回収飛行船 接近」の印でも同時に示す |
| 動きを減らす | 「視差効果を減らす」がオンなら、回収演出のグリッチと画面の揺れを止め、飛行船の影と判子だけにする。ノイズのヒントは、揺れの代わりに紙の汚れが濃くなる表現にする |
| 点滅 | 1 秒に 3 回を超えて点滅させない（光過敏への配慮）。「点滅する光を弱める」がオンなら、赤と青のずれも動かさずに止める |
| 文字の大きさ | ラウンド画面とメニューは Dynamic Type に対応する。献上明細書はシェア画像と同じ固定のレイアウトにし、全項目を VoiceOver で読めるようにする |
| 色 | 安全ラインやヒントを色だけで伝えない。▲の印や文字を一緒に出す |

- **App Store の表記**: アクセシビリティの対応状況は、実機で確かめたものだけを申告する
- **審査**: 審査メモに、設定でタップ操作に切り替えられることを 1 文書き足す（審査担当者が長押しに気づかなくても遊べるように）
- **ダークモード**: 対応しない（2026-11-11 確定）。紙と網点の世界観を崩さないため、ライトに固定する。iOS は Info.plist の UIUserInterfaceStyle を Light、Mac はアプリ全体の外観をライト（aqua）にする。共有シート、課金、Game Center など OS の画面もライトでそろう
- **色を反転したとき**: 「スマート反転」を使う人のために、網点の素材と紙の画像には accessibilityIgnoresInvertColors を付け、写真がネガにならないようにする
- **コントラスト**: 「コントラストを上げる」がオンのときは、薄い文字色（#3F4257）を紺（#1E2340）に、紙の質感を薄くする
- **暗い場所でのまぶしさ**: 地は真っ白ではなく紙の色（#EDE4CF）なので、夜に遊んでもまぶしすぎない。深夜の「夜間割引で回収中」のネタも、画面は暗くせず文言だけで出す

## 価格表の配信と更新

増設価格の単価は、紹介ページと同じサイトに置いた JSON ファイルで配信し、毎月自動で確かめます（2026-11-11 確定）。

| 項目 | 内容 |
| --- | --- |
| 置き場所 | 紹介ページのサイトに prices.json を 1 つ置く。SDK は使わない |
| 中身 | 確認日、地域ごとの 1GB あたりの単価と通貨、比較に使う過去の単価と時点、Mac の機種（hw.model）ごとの単価、出典の URL |
| 取得 | 起動時に 1 回取りに行き、端末に保存する。待つのは 3 秒までで、取れなければ前回の値、それもなければアプリ内蔵の値を使う。どの値でも確認日を画面に出す |
| 地域 | App Store の国（Storefront）で選ぶ。日本は日本の公式ストアの価格を円で、日本以外（アメリカを含むすべての国）はアメリカの公式ストアの価格をドルで出す（2026-11-11 確定） |
| 毎月の確認 | 月 1 回の定期実行で、日本とアメリカの公式ストアの増設価格を調べる。変わっていたら、サイトのリポジトリに更新の PR を作って知らせる。反映は自分で確かめてからマージする |
| 大きな値上げ | ニュースになったら、月 1 回を待たずに手で実行する。値上げ当日に更新できれば、そのまま SNS のネタになる |

- **アメリカの価格**: 1GB あたり $25。MacBook Air（M5）と Mac mini（M6）の 16GB→24GB が +$200、16GB→32GB が +$400（2026-11-11 にアメリカの公式ストアで確認、税抜き）。2025 年 3 月の M4 MacBook Air も +$200 / +$400 で、ドルでは値上がりしていない。日本の 20% の値上がりは、日本向けの価格改定によるもの
- **英語の文言**: 「Mac で増設すると」は「At Mac upgrade prices」のようにし、「公式ストア」は「official store」と書く
- **プライバシー**: サイトのアクセスログに IP アドレスが残る。ログを残さない設定にするか、残すならプライバシーポリシーに書く
- **ドル表示の比較欄**: ドルでは値上がりがないので、「2025年3月比 ▲20%」の代わりに「Still $25/GB. For now.」と出す。値上げされたら、日本と同じように比較を出す
- **税**: 円は税込み（日本のストアの表示）、ドルは税抜き（アメリカのストアの表示）。画面の時点の表記に「税込」「before tax」を添える

## 技術仕様

公開 API だけを使い、安全ラインを越える確保はコード上で不可能にします。

| 用途 | API |
| --- | --- |
| 枠・残量 | `os_proc_available_memory()`（iOS 13 以降） |
| 自分の使用量（検証用） | `task_info(TASK_VM_INFO)` の `phys_footprint` |
| 端末の搭載メモリ（演出用） | `ProcessInfo.processInfo.physicalMemory` |
| メモリ警告 | `UIApplication.didReceiveMemoryWarningNotification`、`DispatchSource.makeMemoryPressureSource` |
| 発熱・省電力 | `ProcessInfo.thermalState`、`isLowPowerModeEnabled` |
| バックグラウンド移行 | SwiftUI の `scenePhase` |

1. **確保**: 16MB ごとに確保し、乱数で埋めます。書き込まないと使用量に計上されず、ゼロ埋めだと圧縮されて数字が動きません。
2. **確保前の判定**: 確保の前に毎回、「献上量＋確保する量 ≤ 枠 × 85%」と「今の残量 − 確保する量 ≥ max(枠 × 15%, 200MB)」の両方を確かめます。満たさなければ確保せず、その時点の量で納品扱いにします（回収ではない）。枠が 600MB 未満のときは遊べないことを案内します。increased-memory-limit の権限は使いません。
3. **即時解放する場面**: ラウンド終了、メモリ警告、バックグラウンド移行、`thermalState` が `.serious` 以上になったとき。
4. **シミュレータ**: `os_proc_available_memory()` が実際の値を返さないため、仮の枠（例: 2GB）で動かします。
5. **検証**: 枠の小さい iPhone、標準的な iPhone、メモリの大きい iPad の 3 種類の実機で、100 ラウンド連続で強制終了しないこと、音楽アプリが裏で止まらないことを確認します。

ランキングに送るのは、スコアと搭載メモリのクラスだけです。端末 ID や正確な搭載メモリ量は送りません。

## Mac 版の技術仕様

Mac には iOS の `os_proc_available_memory()` がなく、アプリ単体の上限で強制終了されることもありません。代わりに、使いすぎると圧縮やスワップで Mac 全体が遅くなるのが問題になるため、端末全体の空きを見て止めます。

| 項目 | 内容 |
| --- | --- |
| 対応 OS | macOS 15 以降（iOS 18 と同じ世代） |
| 作り方 | SwiftUI のマルチプラットフォームで iOS と同じコードを使う。メモリの量り方だけ OS ごとに切り替える |
| 枠 | ラウンド開始時の使用可能メモリ（`host_statistics64` の free + inactive + purgeable）の 60%。ただし搭載メモリの 50% と 32GB を上限にする |
| 安全ライン | 枠の 85%。またはメモリ逼迫が warning になった時点で止める |
| 監視 | 0.5 秒ごとに使用可能メモリと圧縮量を確認し、圧縮が急に増えたら「監査」として止める |
| 配布 | Mac App Store。App Sandbox を有効にする。iOS と同じ Bundle ID にして、課金をユニバーサル購入にする |
| 画面 | 横長の専用レイアウト（最小 1000 × 640）。左にポスターと会長、中央に献上量と長押しボタン、右に回収飛行船と献上中の明細を置き、広げると中央の列が伸びる（2026-11-11 確定）。文字と部品は iPhone と共通。長押しはクリックの押し続けとスペースキーの両方でできるようにする |
| ランキング | 腕前スコアは iPhone・iPad と共通。献上量は Mac 用の搭載メモリのクラス（16GB 以下 / 24–32GB / 48GB 以上）で集計する |

`host_statistics64` で値が取れることは、この Mac（App Sandbox なし）で確認済みです。App Sandbox を有効にした状態でも取れるかは、試作で確かめます。枠の上限を 32GB にしたのは、乱数で埋める速さが追いつく範囲に収めるためです。追いつかないときは確保の速さを頭打ちにし、画面には実際に確保できた量を出します。Mac でも、使用可能メモリは 16MB 確保するたびに確かめます（0.5 秒ごとの監視は圧縮量だけ）。

## 実装の詳細（2026-11-11 の再検討）

仮実装の前に、実装者が推測で埋めることになる点を決めました。ここに書いた内容がほかの節と食い違う場合は、この節を優先します。

### ラウンドの状態と中断

| 状態 | 次へ進むきっかけ |
| --- | --- |
| 待機 | ボタンを押す → 献上中 |
| 献上中 | 離す → 納品の判定。回収ラインを越える → 回収。安全ラインに当たる → 納品。メモリ警告 → 監査（納品扱い） |
| 納品 / 回収 / 監査 | 先に全メモリを解放し、その後で演出を始める → 次のラウンドか結果画面 |
| 無効 | スコア 0、クレジットなし、回収演出なし。「店じまいしました」とだけ出す |

- **離したとみなす**: コントロールセンターや通知で scenePhase が inactive になったとき、タッチがキャンセルされたとき、Mac でウィンドウが前面でなくなったとき（スペースキーを離した通知が届かないため）。通常の納品と同じく回収ラインと比べる
- **無効にする**: バックグラウンドへの移行と、発熱が serious 以上になったとき。ホームに戻るだけで確定できる抜け道をなくすため
- **デイリー**: 無効になっても「挑戦済み」にする
- **定期便の途中で終わったとき**: 確定していない分は「降りた」とみなして確定する。換算献上量は納品したラウンドごとにそのつど保存する（「ゲーム性の見直し」の節）
- **画面は 1 つだけ**: Mac はウィンドウを 1 つに限る（Window）。iPad は複数ウィンドウを使わない（UIApplicationSupportsMultipleScenes = NO）

### メモリの安全

- **回収ラインの上限**: どの取引先でも、動いた後を含めて「安全ライン − 枠の 5%」を越えない。枠が小さく安全ラインが 85% より手前になる端末でも、勝てないラウンドを作らない
- **毎回の確認**: 確保のたびに「献上量」と「今の残量」の両方を確かめる（「技術仕様」の節）。ラウンド中にほかのアプリがメモリを使っても、残量の方で止まる
- **演出の前に解放**: 回収・納品・監査のどれでも、先にメモリを解放してから演出を描く。献上中は新しい画像や音を読み込まない
- **書き込みの負荷**: 乱数で埋める処理は重いので、ページごとに少しだけ乱数を入れる方式でも使用量に計上されるか（圧縮されないか）を試作で確かめる。画面の献上量は、実際に確保して書き込んだ量

### 速達便・デイリーの条件と乱数

- **取引先**: 速達便とデイリーはアロケート社に固定し、取引先の倍率はかけない（2026-11-11 確定）。月末や深夜のネタは文言だけ
- **デイリーの種**: SHA-256("UncleRAM-daily-v1-" + 世界標準時の YYYYMMDD) の先頭 8 バイト。乱数は自前の SplitMix64 で作り、使う順番（回収ライン → ヒントの揺らぎ → 振動の揺らぎ）を固定する。回収ラインは枠に対する割合で全員同じ（MB は端末ごとに違う）
- **式を変えるとき**: v2 として日付で切り替える。別の端末でも同じ値になることを単体テストで確かめる
- **通し番号**: 公開日を #1 とし、世界標準時で数える
- **過去の日付**: /d/<日付> のリンクで過去の日を開いた場合は、ランキングに送らない「練習」として遊べる
- **ニアミス**: 納品が成功したときだけ効く。比べるのは離した瞬間の回収ライン。「手前 1% で拍手」は演出だけで、倍率は ×3 のまま

### 進み方と回収保険

- **称号**: 定期便の累計（換算献上量）だけで数える。50GB / 250GB / 1TB。速達便は含めない（2026-11-11 確定、試作で調整）
- **強化**: 1 段階ごとの価格（ヒント 400 cr × 3 段階、減速 300 cr、保険 600 cr）。保険は使い切り
- **回収保険**: 1 プレイで最大 1 回。支援パックの保険とクレジットの保険は重ねない（支援パックが先に使われ、クレジットの保険は減らない）。発動したら「回収ライン直前の量で納品、ニアミス倍率なし」

### 初回起動と設定

- **初回の案内**: 世界観に合わせた 1 枚で「本物のメモリを使うこと」「裏のアプリが終了することがあること」「端末が速くなるアプリではないこと」を伝え、OK で閉じる。表示したかどうかは端末の中に保存する（iCloud には入れない）
- **練習ラウンド**: 最初の 1 回は回収ラインを枠の 50% に固定し、ヒントを大きく出す。ランキングには送らない（「説明なしで分かる UI」の節）
- **Game Center のサインイン**: 最初のラウンドが終わってから始める。送れなかったスコアは端末に貯めて送り直す（デイリーはその日のうちだけ）。サインイン前の記録は送らない
- **設定の項目**: タップで献上 / BGM の音量 / 効果音の音量 / 振動（iPhone だけ）/ 回収演出を控えめにする / 購入を復元 / 翻訳の誤りを報告 / メモリの使い方について / ライセンス（書体と楽譜と画像の出典）/ プライバシーポリシー / サポート / データの初期化（確認つき）。言語は OS の「アプリごとの言語」に任せる

### 課金と保存の端の場面

- **権利の確認**: 起動時に Transaction.updates を監視し、currentEntitlements で買い切りを確かめ直す。返金（revocationDate）やファミリー共有の解除があれば、スキンと支援パックの保険を外す
- **承認待ち**: Ask to Buy などで pending のときは「承認待ち」と表示する
- **投げ銭**: 回数を記録してから finish() する。返金されても回数は減らさない
- **テスト**: StoreKit の設定ファイルと Sandbox で、返金・Ask to Buy・中断した購入を確かめる
- **iCloud**: 各端末は自分のキーにだけ書く。保存データに schemaVersion を付ける。iCloud のアカウントが変わったら、端末の中のデータは消さずにアカウントごとに分けて持つ。上限（1MB、1,024 キー）を超えないよう、記録は集計値だけを持つ
- **リプレイ動画**: 書き出しは共有のプレビューで始め、進み具合を出して中止できるようにする。バックグラウンドに移ったら中止。一時ファイルは次の起動時にも消す

### 申請に必要なもの

- **プライバシーマニフェスト**: PrivacyInfo.xcprivacy を入れる。理由の申告が必要な API（UserDefaults など）を洗い出して申告する。収集するデータは「なし」を基本にし、サイトのアクセスログの扱いを決めてから確定する
- **暗号化の申告**: ITSAppUsesNonExemptEncryption = NO（HTTPS だけで独自の暗号化はない）
- **URL**: サポート URL、プライバシーポリシーの URL、著作権表記。Universal Links のために Associated Domains の権限と、紹介ページの apple-app-site-association
- **年齢区分**: 新しい年齢区分の質問票に答える（4+ の見込み、App 内課金あり）
- **EU の取引業者の申告**: デジタルサービス法に基づき、会社の住所・電話・メールで申告し、EU でも配信する（2026-11-11 確定）。連絡先は EU の App Store に公開される
- **書体のライセンス**: 使う文字だけに絞った書体は改変版に当たる。書体ごとに予約された名前（Reserved Font Name）がないか確かめ、OFL の文書を同梱する
- **地域**: Storefront が取れないときは Locale.region で円かドルかを決める

### 公開後の確認と試作の合格条件

- **公開後**: Xcode Organizer のクラッシュと終了理由（メモリ上限による終了）、TestFlight のフィードバックで確かめる。MetricKit は端末の中だけで使い、データは送らない
- **試作の合格条件**: 裏で音楽を流し、iPad は Split View でほかのアプリも開いた状態で、次をすべて満たすこと
  - 100 ラウンド続けて、強制終了が 0 回
  - 最高速でも 60fps を保つ
  - メモリの解放が 200ms 以内に終わる
  - Mac でスワップが増えない。App Sandbox を有効にしても host_statistics64 の値が取れる
  - 対象は、枠の小さい iPhone、標準的な iPhone、メモリの大きい iPad、Mac の 4 種類

## ゲーム性の見直し（2026-11-11）

数値で確かめると、回収ラインが 55〜80% にむらなく散らばる作りでは「毎回 55% で離す」がいちばん得になり、押し始めの約 10 秒は何をしても安全でした。押し引きの緊張を保つため、次の 4 点を変えます（2026-11-11 確定）。ほかの節と食い違う場合は、この節を優先します。

### 早期回収

- ラウンドの 1 割は、回収ラインが低い「早期回収」にする。アロケート社は枠の 30〜50%、リアロック・データセンターは 35〜50%（動かない）。カロック・ラボは「低いが安定」の性格を残すため、早期回収なし
- 早期回収のラウンドでもヒントは普段どおり出る。ヒントを読めば避けられる
- デイリーも同じ扱い。乱数を使う順番は、早期回収かどうか → 回収ライン → ヒントの揺らぎ → はったり → 振動の揺らぎ（「実装の詳細」の節の順番を置き換える）
- 早期回収で回収されたときは、結果に「抜き打ち回収」の判子を押す

### ヒントの出方

| 段階 | 見せ方 | 出る位置（回収ラインの手前） | 揺らぎ | ヒント精度アップの効き目 |
| --- | --- | --- | --- | --- |
| 1. 気配 | 会長の表情が変わる | 枠の 15% | ±4% | 1 段階ごとに揺らぎが 25% 減る |
| 2. 接近 | 回収飛行船の音が近づく | 枠の 8% | ±2.5% | 1 段階ごとに揺らぎが 25% 減る |
| 3. 警告 | 画面にノイズが走る | 枠の 2% | ±2% | 変わらない |

- 段階は必ず 1 → 2 → 3 の順に出る。揺らぎで順番が入れ替わるときは、後の段階を少し後ろにずらす
- 3 の警告は「もう手遅れかもしれない」合図。ここで離しても、反応の遅れ（約 0.25 秒）で半分ほどは回収される
- **はったり**: 15% のラウンドで、会長が偽の「気配」を見せる。枠の 15〜70% のどこかで表情が変わり、1 秒でにやりと笑って戻る。接近と警告の偽物は出さない
- 振動も段階に合わせて出す（「音と振動」の節）。はったりのときも振動する

### 献上の速さ

- 枠の 30% までは 10%/秒（約 3 秒）。30% から先は 5%/秒で始め、1 秒ごとに 10% ずつ速くなり、上限は 9%/秒
- 目安: 30% まで 3.0 秒、55% まで 7.1 秒、80% まで 10.1 秒
- 速さは枠に対する位置だけで決め、回収ラインには左右されない（速さからラインが読めないように）
- 長押し減速の強化は、30% から先の速さを 2 割落とす

### 定期便の「降りる・続ける」

- 定期便は最大 5 ラウンド。納品に成功するたびに「降りる」か「続ける」を選ぶ
- **降りる**: それまでの合計スコアとクレジットを確定してプレイを終える
- **続ける**: 次のラウンドへ。ラウンドの倍率が 1 ラウンド目 ×1.0、2: ×1.2、3: ×1.5、4: ×2.0、5: ×3.0 と上がる。5 ラウンド目を終えたら自動で確定
- **回収されたら**: 確定していないスコアとクレジットをすべて失い、プレイを終える。回収保険が効いたときは失わず、次を選べる
- **換算献上量**（称号とリアロックの解放に使う累計）は、回収されても納品済みのラウンドの分を数える。献上した事実は消えない、という扱い
- **途中で終わったとき**（アプリの終了・無効）: 確定していない分は「降りた」とみなして確定する。引き際は離す方が常に得なので、抜け道にはならない
- **スコア** = 献上量 × ニアミス倍率 × 取引先の倍率 × ラウンドの倍率

### 試算

アロケート社、反応の遅れ 0.25 秒、乱数で 6 万回遊んだ場合の結果です。期待値は「離した位置（枠に対する %）× ニアミス倍率」の平均です。

| 遊び方 | 期待値 | 回収される割合 |
| --- | --- | --- |
| 毎回 55% で離す | 68 | 10% |
| 気配で離す | 53 | 0% |
| 接近で離す | 88 | 0% |
| 接近の後、さらに 2% 押す | 121 | 0% |
| 接近の後、さらに 4% 押す | 138 | 12% |
| 警告で離す | 87 | 54% |
| 接近の後、さらに 4% 押す（ヒント精度を 3 段階まで強化） | 185 | 0% |

- 決まった位置で離すより、ヒントを読んでぎりぎりまで押す方が得になり、腕前の差が出る
- ヒント精度を最後まで強化すると強すぎる。定期便はランキングに入らないので許すが、試作で価格と揺らぎの減り方を調整する
- 試算に使ったスクリプトは引き継ぎ一式の tools/sim.py

## 説明なしで分かる UI（2026-11-11）

説明文を読ませず、画面の作りと 1 回目の体験で分からせます。強制する説明は会長の短い吹き出しだけにし、一度に 1 つ、20 字前後に収めます。初回の案内（本物のメモリを使うことなど、「初回起動と設定」の節）は安全のために残します。

### 最初の 1 回で覚えること

最初の 1 回は練習ラウンド（回収ラインは枠の 50% に固定）です。次の順に、その場面が来たときだけ吹き出しを出します。

| 覚えること | 見せ方 | 文字 |
| --- | --- | --- |
| 押している間だけ献上 | ボタンそのものに文言を書く。押す前はボタンが脈打ち、押すとゲージが伸びて数字が増える | 「長押しで献上」（ボタンの文言） |
| 離すと納品 | ゲージが 20% に来たら吹き出し | 「離せば納品だ」 |
| ヒント | 各段階が初めて出たとき、その兆しのすぐ横に一言。練習ラウンドでは兆しを大きく出す | 「会長の機嫌が変わった」「飛行船が近い」「もう危ない」 |
| 越えると回収 | 回収されてもされなくても、結果でゲージにラインの位置を描く | 「ラインはここだった」 |
| ニアミス | 結果のゲージに、離した位置とラインの差を描き、倍率の判子を押す | 「あと 2%！」など、差を数字で |

### 画面の作りで伝えること

- **ゲージの濃淡**: 献上ゲージの背景に、取引先の回収ラインが散らばる範囲を薄い色の濃淡で描く。アロケート社なら 55〜80% が濃く、30〜50% にもうっすら色を置く。どこから危ないかが読まずに分かる。そのラウンドのラインそのものは見せない
- **結果でラインを明かす**: 速達便と定期便では、毎ラウンドの結果でラインと離した位置をゲージに並べる。負けた理由も、もう少し押せたかも一目で分かる
- **デイリーだけは明かさない**: その日のうち（世界標準時の 0 時まで）はラインの位置を出さず、「納品」「回収」とニアミスの判子だけにする。全員が同じラインなので、ネタばれでほかの人の挑戦が崩れないようにする。翌日からは「練習」で見られる
- **はったりの種明かし**: 偽の気配が引っ込むとき、会長がにやりと笑う。初めてのときだけ吹き出し「…なんてな」
- **降りる・続けるのボタン**: 2 つの大きなボタンに結果をそのまま書く。「降りる +120 cr 確定」「続ける 次は ×1.5 / 回収されたら 120 cr 没収」。確定していない分は、帳簿に「未確定」の判子つきで積む
- **早期回収**: 初めて当たったとき、判子「抜き打ち回収」と吹き出し「たまに早いこともある」
- **Mac**: ボタンの文言を「スペースを長押し」にする（クリックの長押しでも遊べる）

### 少しずつ開く

- 初回は速達便だけを遊ぶ。1 回終えると、定期便とデイリーのボタンが開く
- 定期便の初回で「降りる・続ける」を初めて見せる。1 ラウンド目の後に一度だけ吹き出し「欲張るか、帰るか」
- 強化の店は、初めてクレジットが貯まったときに開く
- リアロック・データセンターは、解放したときにラインが動く様子をゲージの上で 1 回だけ見せる

### いつでも見られる説明

- タイトルとラウンド画面の「?」から、絵だけの 3 コマ（押す → 兆しを見る → 離す）を開ける。読まなくても遊べる前提なので、強制しない
- 吹き出しは設定の「使い方をもう一度見る」で元に戻せる
- VoiceOver では吹き出しを読み上げ、ヒントは文字でも出す（「アクセシビリティ」の節）

### 試作で確かめること

- 初めての人が説明なしで、最初の 1 回のうちに「離すと納品」が分かるか。5 人に遊んでもらい、最初の 1 回で納品できた人数を見る
- ゲージの濃淡が、そのラウンドのラインのネタばれに見えないか
- はったりが「理不尽」ではなく「やられた」と感じられるか

アプリは template-app-ios から作ります。Bundle ID はテンプレートの命名に合わせて jp.shilokuma.UncleRAM にします（2026-11-11 確定。rename.sh に渡す名前も UncleRAM）。

| 識別子 | 値 |
| --- | --- |
| Bundle ID（iPhone・iPad・Mac 共通） | jp.shilokuma.UncleRAM |
| テストターゲット | jp.shilokuma.UncleRAM.Tests / .UITests（テンプレートで自動で派生） |
| SKU | jp.shilokuma.UncleRAM（テンプレートの決まりで Bundle ID と同じ） |

| App 内課金 | jp.shilokuma.UncleRAM.supportpack / .skinpack / .tip160 / .tip480 / .tip980 |

- **Mac の権限**: App Sandbox、外部への通信（価格表の取得）、iCloud、Game Center を有効にする
- **CI**: テンプレートの Archive / Upload のワークフローは iOS だけなので、Mac 用の Archive・Export・Upload を足す。スクリーンショットの撮影ツール（Tools/）も 9 言語と Mac に広げる
- **管理の場所**: 識別子はテンプレートの方針どおり Configs/Project.xcconfig にまとめ、課金とランキングの ID はコードの 1 か所に定数として置く

## 世界観・キャラクター・文言

実在の人物・企業・ロゴは一切出さず、「巨大 AI 企業が個人のメモリを集めて回る近未来」という架空の世界にします。

- **設定**: メモリが石油より高くなった世界。各家庭の端末から「使っていないメモリ」を集める巨大 AI 企業「アロケート社」の「回収飛行船」が飛んでいます（観た目は 1910 年ごろの飛行船の写真を網点にしたもの）。
- **CEO**: アロケート社のマロック会長（C 言語の malloc のもじり）。笑顔を絶やさない、顔の見えないシルエットの人物です。実在の経営者に似せた顔・髪型・名前は使いません。
- **プレイヤー**: 「提供者」と呼ばれます。小市民的な抵抗と欲の間で揺れる立場です。
- **トーン**: 会社的な丁寧語で、過剰に感謝してくる皮肉です。特定の個人や集団を攻撃する表現は使いません。
- **文言の例**（オリジナル。パロディサイトの文面は流用しない）:
  - 「その空き、もったいなくありませんか？」
  - 「効率化へのご協力、心より感謝申し上げます」
  - 「あと少しだけ、あと少しだけですので」
  - 回収時:「ご提供いただいた全メモリは、当社が責任をもって有効活用いたします」

元ネタ（「AI のために、個人が抱えているメモリを回収したい」）を伝えるため、次の 3 つを世界観の軸にします。実在の人物の名前や発言の引用は使いません。

- **社是**: 「全人類の RAM を、ひとつの AI に。」。タイトル画面の社名の横に置き、アロケート社は「巨大 AI 企業」と明記する
- **会長の主張**: 「個人の端末にメモリを置いておくのは、資源の無駄遣いです」「その RAM、ほとんど使われていませんよね？」「空いているメモリは、効率よく使われるべきです」など、主張の趣旨をなぞる言い回しを繰り返す
- **時事性**: 献上したメモリを公式ストアの増設価格で換算し、「2025 年 3 月比 ▲ 20%」のように本物の値上がりを見せて、高騰のニュースと重ねる（詳しくは「金額の表示」の節）
- **用途のしょぼさ**: 献上明細書に「用途: AI の学習（推定 0.0003 秒分）」の欄を置き、差し出した量に対して使い道が一瞬であることを笑いにする。秒数は献上量から計算する架空の値

## ネタの詰め込み方

ネタは「端末の本物の状態に反応する」ものを中心にします。自分の端末でしか見られない反応は、スクショにして投稿したくなります。

| きっかけ（実データ） | ネタ |
| --- | --- |
| 搭載メモリ | 初回起動時の CEO の態度が変わる。小さい端末には「……まあ、いいでしょう」、大容量の iPad には「上客様がお見えです」 |
| 省電力モード | 「省電力モードとは、非協力的ですね」 |
| 発熱（`thermalState`） | 「データセンターも大変なんです」と休憩をすすめ、実際にプレイを止める（安全対策を兼ねる） |
| メモリ警告 | 「監査が入りました」。スーツの監査役が画面を横切る |
| 時刻 | 深夜は「夜間割引で回収中」。月末は「四半期のノルマが……」。どちらも文言だけで、回収ラインは変えない |
| 前回の結果 | 起動時に「前回は 2.3GB のご提供、ありがとうございました。さて」 |
| 献上量 | 換算表示。「ブラウザのタブ約 40 枚分」「Mac で増設すると ¥5,480 相当」（公式ストアの増設価格から換算。時点を明記する） |
| ニアミス | 回収ラインの手前 1% で止めたら、CEO が拍手しながら惔しがる |

- **リザルト画面を給与明細風にする**: 「支給: 感謝の言葉」「控除: 空きメモリ 3.1GB」のように、一時停止して読むと笑える小ネタを詰め込める場所にします。
- **社内報フィード**: ラウンドの合間に、架空の企業の社内報が流れます。実在の SNS の見た目は真似ません。
- **代替アイコン**: 称号を取ると解放されます。ホーム画面でネタが続きます。
- **注意**: 「メモリを解放して端末が速くなる」という風に読めるネタは入れません。事実として誤りで、1.1.6 に引っかかります。

## アプリ名

アプリ名は「**Uncle RAM**」（アンクル・ラム）に決めました。有名な募兵ポスターの Uncle Sam（パブリックドメイン）に掛けた名前で、実在の人物の姓は入れません。キャッチコピーは「I WANT YOUR RAM」です。以下は検討した候補です（ほかに RAMSAM、SamuRAM も検討）。

| 候補 | 狙い | 注意 |
| --- | --- | --- |
| RAM 献上 / RAM Tribute | 「今日は 4.2GB 献上した」と言いやすい | 同名アプリは未確認 |
| メモリ・チキンレース | 遊び方が名前で分かる | ミーム感は弱い |
| 空きメモリ回収局 | 役所っぽさが小ネタのトーンと合う | 「メモリ解放アプリ」と誤解されないよう説明文で補う |
| Give Me Your RAM | 英語圏でもそのまま通じる | 日本語では弱い |
| メモリ税 | 短くて強い | 税金アプリと混同されやすい |

名前・サブタイトル・キーワードには、実在の人名・企業名・製品名（元ネタになった AI 企業とその経営者・製品の名前など）を入れません。2.3.7、4.1(c)、5.2.1 に引っかかるためです。2026-11-11 時点の Web 検索では、「Uncle RAM」という名前の iOS アプリやゲームの商標は見つかりませんでした。ただし、「RAM」は自動車ブランドの登録商標でもあるので、公開前に J-PlatPat と USPTO で区分 9・28・41 を確認します（[検索結果の例: RAM® アプリ](https://apps.apple.com/app/1565972415)、[ゲーム商標の調べ方](https://mekiplaw.com/how-to-trademark-a-game-the-ultimate-guide)）。メモリ解放を謳った機能が過去に Apple から削除を求められた例もあり（[iLounge](https://www.ilounge.com/index.php/news/comments/apple-forcing-removal-of-free-memory-app-features)）、1.1.6 の方針を裏付けています。

| 地域 | 受け取られ方 | 対応 |
| --- | --- | --- |
| アメリカ | 最も刺さる。「I WANT YOUR RAM」が即座に伝わる | そのまま |
| イギリス・カナダ・豪州 | 通じる。イギリスには元になった自国の募兵ポスターもある | そのまま |
| 日本 | 名前より絵で伝わる。「アンクル・サム」を知らない人も多い | サブタイトルで内容を説明する（例:「空きメモリ、いただきます」） |
| ヨーロッパ大陸 | ポスターは通じるが、Uncle のダジャレは弱め | 各言語のサブタイトルで補う |
| インド・ネパール | 「Ram」はヒンドゥー教の神の名前で、男性の名前としても一般的。「ラムおじさん」や宗教的な表現と取られるおそれがある | ロゴでは RAM を必ず大文字にする。反応が悪ければ配信地域から外す（1.1.1 の宗教への配慮） |

## SNS でバズるための戦略

勝負どころは「ミームが話題になっているうちに出すこと」と「機種ごとに結果が違うことを端末自慢に変えること」の 2 つです。

1. **速さ**: 初回から全機能（速達便・定期便・取引先 3 社・強化・課金）を入れて出します（2026-11-11 確定）。その分、公開までに間が空くので、開発中から速達便の動画を SNS に出して話題をつなぎ、TestFlight の公開テストも早めに始めます。公開日は日付では置かず、できしだいすぐに出します（「公開までの段取り」の節）。
2. **シェア画像**: 端末名、献上量、称号、給与明細風の小ネタを 1 枚にします。「iPad Pro 勢 vs iPhone SE 勢」のような対抗を生みます。
3. **ハッシュタグ**: 「#UncleRAM」をシェア画像に、「#UncleRAM #メモリ高騰」をシェアの初期文面に入れておきます。アプリの外の投稿（開発者の SNS など）では、メモリ高騰と「個人の RAM は非効率」論という時事の文脈をもう少し直接に出します。実在の人物名は使いません。
4. **デイリーチャレンジ**: 全員が同じ条件で遊ぶので、「今日の回収ライン厳しすぎ」など、毎日話題が生まれます。
5. **配信映え**: ニアミスや回収の演出を大きくし、画面収録でも分かる音を付けます。公開前に TestFlight の公開テストで配信者に試してもらいます。
6. **英語対応**: ミームは英語圏発なので、公開時から英語に対応します。Reddit（r/pcmasterrace など）、Hacker News、X に短い動画を投稿します。
7. **紹介ページ**: 1 ページの Web サイトに、動画・App Store リンク・ランキング上位を置きます。

### 共有機能

結果は「画像」「動画」「文字」の 3 つの形で共有できます（2026-11-11 確定）。どれも本人が共有シートから投稿し、アプリからの自動投稿や、共有と引き換えの報酬はありません。

| 形 | 中身 | 作り方 |
| --- | --- | --- |
| 画像 | 献上明細書。4:5（1080×1350）を基本に、ストーリー用の 9:16（1080×1920）も選べる | アプリの中で ImageRenderer で書き出す。遊んだ人の言語と通貨になる |
| 動画 | 縦型 9:16、約 10 秒のリプレイ。献上が加速し、ニアミスで止めるか回収されるまでを、音つきで少し速めて見せる。最後に明細書と「#UncleRAM」 | ラウンド中は献上量・ヒントの段階・結果だけを記録し（数 KB）、メモリを解放した後、共有するときに AVAssetWriter で動画にする。画面収録はしない。動画は共有後に削除する |
| 文字 | デイリーと速達便の結果を絵文字つきで。例は下 | 言語ごとの定型文に値を入れる |

文字の共有の例（デイリー）:

```text
Uncle RAM デイリー #12（11/11）
🟥🟥🟥🟥🟥🟥🟥⬜⬜⬜ 納品成功
献上 2,410MB（ニアミス ×3）→ 買取額 ¥0
iPhone 17 Pro（12GB）
#UncleRAM https://（紹介ページ）/d/20261111
```

- **絵文字の意味**: 10 マスが枠に対する献上率（10% 刻み）。回収されたら最後のマスを「💥」にして「全メモリ回収」と書く
- **ネタバレを防ぐ**: デイリーは全員が同じ回収ラインなので、画像・動画・文字のどれにも回収ラインの正確な位置は出さない。答えは翌日、アプリの中で「昨日の回収ライン」として見せる
- **共有の入口**: リザルト画面の「明細書をシェア」、回収演出の後、デイリーの結果。押すと共有のプレビュー画面が開き、画像・動画・文字を切り替えてから共有する。「画像を保存」と「文字をコピー」も置く
- **端末の表示**: 標準は「iPhone 17 Pro（12GB）」「MacBook Air（M5・24GB）」のような機種名＋搭載メモリ。共有のプレビュー画面に「機種名を隠す」を置き、オンにすると「iPhone（12GB 級）」になる。選んだ内容は次回も使う
- **機種名の対応表**: 機種 ID（iOS は utsname、Mac は hw.model）と機種名の対応表をアプリに持ち、価格表と同じ JSON で新機種を足せるようにする。表にない機種は「iPhone（12GB 級）」のように級だけで出す。メモリは physicalMemory を 8 / 12 / 16GB などの正式な容量に丸める
- **リンク**: 紹介ページの URL を付ける。デイリーは /d/<日付> にし、アプリが入っていれば Universal Links でその日のデイリーを開く。入っていなければ App Store への案内と、その日の OGP 画像を出す。URL には利用者を特定できる情報を入れない
- **初期文面**: 言語ごとに用意する。「#UncleRAM」は共通、日本語は「#メモリ高騰」も入れる
- **共有できる中身の範囲**: 機種名・献上量・称号・金額だけ。名前や端末の ID は載せない
- **権限**: 「画像を保存」のために、写真への追加の許可（NSPhotoLibraryAddUsageDescription）を入れる。説明文は 9 言語分用意する
- **Mac**: 同じプレビュー画面と共有メニューを使う。画像はクリップボードへのコピーもできるようにする

### ランキング

全端末で公平に競う「腕前スコア」と、端末自慢のための「献上量」の 2 本立てにします（2026-11-11 確定）。枠は裏で動くアプリによって毎回変わるので、クラスは枠ではなく、変わらない搭載メモリで分けます。

| ランキング | 数え方 | 分け方 |
| --- | --- | --- |
| 腕前スコア | 回収ラインへの到達率（納品量 ÷ 回収ライン × 100）× ニアミス倍率。最大 300 pt、回収されたら 0 pt | 全端末で 1 本 |
| 献上量 | 今と同じスコア（献上量 MB × ニアミス倍率） | iPhone / iPad: 8GB 以下 / 12GB / 16GB 以上。Mac: 16GB 以下 / 24–32GB / 48GB 以上 |

- **対象のモード**: 速達便とデイリーのそれぞれに、上の 2 種類を置く（腕前 1 本＋献上量 6 本 × 2 モード = 14 本）。デイリーは Game Center の繰り返し型ランキングで毎日リセットする。定期便は強化や保険が効くので集計しない
- **画面**: 最初に腕前スコアを見せ、「献上量」に切り替えると自分のクラスが開く。ほかのクラスも見られる
- **クラスの決め方**: physicalMemory を正式な容量に丸めて決める。同じ端末ならずっと同じクラスになる
- **Mac の上限**: Mac は枠の上限が 32GB なので、48GB 以上のクラスは全員が同じ上限で競うことになる。事実上、腕前の勝負になる
- **不正なスコア**: 腕前スコアが 300 pt を超えるもの、献上量がそのクラスの搭載メモリを超えるものは送らない。送られた異常なスコアは App Store Connect から消す
- **シェアとの関係**: 明細書と文字の共有には、腕前スコアとクラス内の順位の両方を載せられるようにする

### Game Center と名前の扱い

ランキングは Game Center だけで作り、アプリ独自のサーバーや、自由入力のユーザー名は持ちません（2026-11-11 確定）。利用者が書いた文字をほかの利用者に見せる仕組みを自分で運営しないことで、電気通信事業法の届出や外部送信規律の検討、不適切な名前の監視、審査 1.2（利用者が作るコンテンツ）の対応を避けます。

| 項目 | 内容 |
| --- | --- |
| 名前 | Game Center のニックネームをそのまま表示する。名前の登録・変更・不適切な名前への対応は Apple が行う。アプリに名前を入力する欄は置かない |
| ランキングの画面 | GKLeaderboard から順位を読み、明細書風の自前の画面で見せる。「全体」と「友だち」を切り替えられる。Game Center の標準画面への入口も置く |
| 端末の表示 | スコアに付けられる数値（context）に端末の種類とメモリのクラスを入れ、「○○（iPad・16GB）」のように添える。機種名までは送らない |
| デイリー | 繰り返し型のランキング（期間 1 日）。切り替えは世界標準時 0 時（日本時間 9 時）。デイリーの乱数の種と共有リンクの日付も世界標準時で数える |
| 実績 | 称号を実績にもする。優良提供者・模範的な提供者・名誉株主と、特別な称号（満額寸前の人、空き容量の守り人）。ID は jp.shilokuma.UncleRAM.ach.<称号> |
| チャレンジ | Game Center のチャレンジに対応し、「友だちと速達便で勝負」を作れるようにする。加えて、デイリーをアクティビティとして登録し、Games アプリから直接開けるようにする。どちらも iOS 26 / macOS 26 以降だけの機能なので、それより前の OS では入口を出さない |
| サインインしていない人 | 遊ぶことはできる。自分の最高記録だけを端末に残し、ランキングの画面で Game Center へのサインインを案内する。スクリーンタイムで Game Center が制限されている場合も同じ |
| 端末の間 | iPhone・iPad・Mac で同じ Game Center アカウントとランキングを使う |

- **シェアとの切り分け**: シェア画像や文字には Game Center のニックネームを載せない。明細書は「提供者 殿」のままにする
- **プライバシー**: アプリが受け取るのは Game Center のプレイヤー ID とニックネームだけで、保存も送信もしない。App のプライバシー表記は、提出前に Apple の最新の説明で確かめる
- **審査**: ランキングと実績は、最初の審査でアプリと一緒に提出する。後から足すものも、新しいバージョンと一緒に審査される
- **法律の確認**: 自由入力を持たない構成は届出がいらない前提だが、専門家の判断ではない。将来、コメントやチャットのように利用者同士がやり取りする機能を足すときは、総務省の届出の案内で確かめる

シェアは共有シート（`ShareLink`）から本人が投稿する形にし、アプリからの自動投稿はしません。報酬と引き換えにシェアやレビューを促すこともしません。

## 収益化

広告は入れず、App 内課金だけにします。広告 SDK のメモリ消費、ATT の許可、広告向けのプライバシー表記がいらなくなり、審査も単純になります。

| 商品 | 種類 | 価格（案） | 中身 |
| --- | --- | --- | --- |
| 支援パック | 買い切り | ¥480 | 定期便で毎回回収保険が 1 回つく。限定スキン（金のシルクハット）と明細書の特別デザイン |
| 社章スキン集 | 買い切り | ¥240 | 明細書・判子・飛行船の色違い |
| 会長への特別賞与（投げ銭） | 消耗型 | ¥160 / ¥480 / ¥980 | 何ももらえない。専用のお礼のセリフと、明細書の「特別賞与」欄だけ |

- iPhone / iPad / Mac は同じ Bundle ID のユニバーサル購入にし、どれかで買えば全部で使えるようにします。
- 保険は定期便だけで効き、ランキングを集計する速達便とデイリーには影響しません。
- 投げ銭は、購入前の画面で「ゲーム内で得られるものはありません」と明記します。
- **商品は 3 つだけ**: 季節の限定スキン、グッズ販売、明細書の名入れも検討したが、初回は入れず、公開後の売れ方を見て判断する（2026-11-11 確定）
- **ドルの価格**: 支援パック $2.99、社章スキン集 $1.99、投げ銭 $0.99 / $2.99 / $5.99。日本は円の価格、そのほかの国はアメリカを基準に App Store Connect の自動換算を使う
- **手数料**: App Store Small Business Program に申し込み、手数料を 15% にする（年間の売上が 100 万ドル以下の開発者が対象）。公開前に申し込む
- **外部決済**: 使わない。日本やアメリカでは外部の決済へのリンクも認められてきたが、金額が小さいので StoreKit だけにして審査と実装を単純に保つ
- **ファミリー共有**: 買い切りの 2 商品はファミリー共有を有効にする。投げ銭は対象外
- **購入の復元**: 設定に「購入を復元」を置く（3.1.1）
- **購入の画面**: 支援パックの回収保険が効くのは定期便だけで、ランキングには影響しないことを購入前に書く
- **投げ銭の笑い**: 購入すると、明細書の「特別賞与」欄に「会長の飛行船の燃料代（推定 0.2 秒分）」のようなしょぼい使い道が載る。「何ももらえない」こと自体をネタにする
- **収益の見込み（大まかな目安）**: ダウンロードの 2% が平均 ¥550 を使うとすると、手数料 15% を引いた手取りは、10 万ダウンロードで約 93 万円、30 万で約 280 万円、100 万で約 935 万円。バズった時の上振れを取る作りで、継続的な収入は期待しない
- **公開後に見る数字**: 購入率、商品ごとの売れ方、投げ銭の金額の内訳。App Store Connect の分析だけで見る（分析用の SDK は入れない）。公開 2 週間後に、季節スキンなど追加の商品を検討する
- 「課金すると端末のメモリが増える・速くなる」と読める表現は使いません（1.1.6、2.3.1）。ランダム型の商品は作りません。

## 審査メモ（App Review Notes）の文案

審査担当者が「メモリを大量に使う」「画面が崩れる」を不具合と誤解しないように、仕組みを先に書いておきます。App Store Connect には英語で書きます。

```markdown
This is a push-your-luck game. While the player holds the button, the app allocates real memory in 16 MB chunks and shows the actual numbers reported by os_proc_available_memory().

Safety design:
- On iPhone and iPad, allocation always stops at 85% of the app's available memory budget, so the app is never terminated by the system. On Mac, the budget is capped at 60% of available system memory (at most 50% of physical memory or 32 GB), and allocation stops as soon as the system reports memory pressure.
- All allocated memory is released immediately at the end of each round, on memory warnings, when thermal state becomes serious, and when the app moves to the background.
- The "collection" effect when a round is lost is an in-game animation in the game's own art style. It does not imitate iOS system screens, crashes, or the Home Screen.
- The app does not claim to free memory or improve device performance.

How to test: Tap Start, then press and hold the large button. Release before the hidden line to bank your score. If holding is difficult, turn on "Tap to Donate" in Settings to start and stop with single taps.
```
